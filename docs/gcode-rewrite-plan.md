# План: переработка генерации G-code (`js/export/gcode.js`)

Статус: черновик плана, реализация не начата. Эталонные УП: `docs/reference/*.nc`.

## Текущее состояние

- Один `.tap` на пару (сторона, инструмент): `<order>-{лиц|тыл} ф<d>х<len>.tap`.
- Инструменты `TOOLS`: 4x17, 4x22, 8x32, 8x42; обороты, подача, глубина за проход, шаг — заглушки.
- `pickTool`: глубина ≤ 15 мм → 4x17; иначе 8x32 (плита 30 мм) или 8x42 (≥ 40 мм).
- Вывод только G1 (нет G2/G3), ClipperLib offset (масштаб 1000×, 96 сегментов на окружность).
- Зигзагообразный вход (`buildRampedPass`), Z=0 на поверхности стола, safeZ = толщина + 10.
- Зеркалирование X для нижней стороны, ориентация vertical = поворот на 90° CCW.
- millType: outside / inside / contour / pocket (концентрические кольца).
- `layers.js` → `machining` (side/depth/depthAnchor/millType) — заглушки.

### Проблемы

- Режимы резания — заглушки.
- ClipperLib не проверен в браузере на реальных данных.
- Тесты удалены 2026-10-14.
- Нет G2/G3, нет перемычек (tabs) / «шкурки» для сквозных резов.
- Лишние подъёмы, Z-ноль на столе, а не на плите.

## Целевая архитектура

### 1. Конвейер

`entries → operations → toolpaths → ordering → post-processor → text`

- **operations** — из machining-профиля (что и чем обрабатывать).
- **toolpaths** — только геометрия с уровнями Z, без диалекта.
- **post-processor** — единственная часть, знающая диалект: header/footer, формат чисел, смена инструмента, окончания строк. Новый контроллер = новый post.

### 2. Machining-профиль как данные

- Инструменты, подачи/обороты по материалу и толщине, глубина за проход, шаг, правила выбора инструмента.
- `layers.js` оставляет только стиль и семантический тип (сквозной рез, карман, гравировка).

### 3. Качество траекторий

- Настоящие G2/G3 (**приоритет**, станок поддерживает) (arc-fit результата Clipper или аналитический offset окружностей/дуг).
- Карманы через Clipper PolyTree (острова).
- Чистовой проход по стенкам; доработка остатка (rest machining: 4 мм после 8 мм).
- Спиральный вход для отверстий; рампа для контуров; lead-in/out.
- Climb / conventional на операцию.

### 4. Порядок обработки

- Сначала карманы и отверстия, внешний контур последним.
- Nearest-neighbor; глубина «до конца» по контуру, без лишних подъёмов.

### 5. Превью и проверки

- Оверлей траекторий, время обработки, проверка границ.
- Предупреждения: Z ниже стола, карман уже инструмента, самопересечения.

### 6. Опционально

- Z-ноль на поверхности плиты.

## Порядок работ

1. Конвейер + профиль + post-processor; вывод по формату эталонных `.nc` (NCStudio).
2. G2/G3, порядок обхода, вход/выход.
3. Карманы с островами, чистовой проход.
4. Превью и проверки.

## Ответы владельца (2026-11-08)

- ПО станка: **NCStudio 5.5.60**. Эталонные `.nc` — рабочие, из реального производства (не «идеальные»).
- **Перемычки не нужны**: столешница режется из мебельного щита в размер, держится на вакууме.
- **Приоритет — простота**; качество/скорость — позже. Текущие режимы резания работают терпимо.
- Реальные условия: тупые фрезы, плохой материал, слабый вакуум, неточный станок → не усложнять, оставить настройки легко правимыми.

## Что видно в эталонных `.nc` (DSK1141, плита 40 мм)

Формат (держать побайтно близким к эталону):
- Шапка: `T1M6`, `G17`, `G0Z50.000`, `G0X0.000Y0.000S<об>M3`; конец: `G0Z50.000`, `G0X0.000Y0.000`, `G0Z50.000`, `G0X0.000Y0.000`, `M30`. Файл заканчивается пустой строкой.
- Безопасная высота **Z50** (фиксированная, не толщина+10). Подача `F` задаётся в строке первого `G1Z` на операции.
- Координаты с 3 знаками; **модальный вывод** — повторяющиеся X/Y/Z и `G1` опускаются (`G1X..`, потом просто `X..Y..`).
- Z-ноль на поверхности стола; верх плиты = Z40.
- **G2/G3 используются активно** (дуги в I/J, относительные), станок их поддерживает. Окружности — 4 дуги G3 по 90°; контуры — смесь G1 и G2/G3.

Параметры по инструментам:
| Файл | Фреза | Обороты | Подача | Z-диапазон | Примечание |
|---|---|---|---|---|---|
| 4_17 (лицо) | ф4х17 | S24000 | F3000 / F6000 | 25…50, 34.5…50 | эталон лицевой стороны, гравировка/пазы |
| 8_42 | ф8х42 | S18000 | F4000 | **0…50** | сквозной рез **до Z0**, без «шкурки» |

Приёмы, которые уже используются в эталоне:
- Спиральный (винтовой) вход для отверстий: G1-спираль вниз с шагом ≈1–1.5 мм на виток, затем чистовой круг G3.
- Зигзаг-рампа для контуров/карманов: движение туда-обратно с постепенным снижением Z (шаг порядка 2.7 мм на проход для ф8).
- Отверстия делаются концентрическими кольцами G3 (расширяющимися) до нужного диаметра.
- Карманы — вложенные контуры внутрь (offset внутрь с шагом ≈3 мм для ф4).
- Мелкие отверстия — спираль + финишный круг, пары проходов (грубо/чисто).

Выводы для плана:
- Этап 1 (рефакторинг с идентичным выводом) цель — **совпасть с форматом эталона**: шапка/футер, модальный вывод, Z50, `F` в первом `G1Z`, 3 знака.
- G2/G3 — не «опционально»: станок их ест, эталоны ими пользуются. Переносим в этап 2, раньше «карманов с островами».
- Перемычки/«шкурку» из плана **убрать**.
- Сквозной рез до Z0 — норма (проверить, что пока совпадает с `resolveDepth`).
- Приоритет «простота»: профиль режимов — один понятный файл/объект с текущими рабочими значениями (из эталонов), без сложной логики rest machining на первом этапе.

## Ограничения проекта

Vanilla JS без сборщика, запуск с `file://` через `<script defer>` в порядке загрузки, LF, паттерн `const X = (() => {...})()`, геометрия через `Geo.*`, `Layers.registry` — единый источник стиля/машинной обработки, Decimal.js для точности экспорта, библиотеки в `vendor/`. Тесты в репозитории пока не ведём (решение 2026-10-14).
