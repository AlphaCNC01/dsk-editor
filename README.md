# DSK Editor — monorepo

## Структура

```
packages/          — общее ядро, используется всеми приложениями
  core/             — геометрия (geo.js), реестр слоёв (layers.js),
                      реестр элементов (elements.js), сборка чертежа (drawing.js)
  elements/         — каталог встраиваемых элементов (зарядки, розетки,
                      подстолье, кабель-каналы и т.д.)
  render/           — превью (SVG для экрана, размерные линии)
  export/           — DXF/SVG/PNG/G-code экспорт

apps/               — отдельные приложения поверх общего ядра
  engineer/         — сегодняшний редактор (полный функционал), Vite-проект
  geometry-editor/  — пока не перенесён (следующий шаг)
  client/           — ещё не создан (будущий шаг)
```

Каждый пакет — обычные ES-модули (`import`/`export`), без сборки. Каждое
приложение в `apps/` — отдельный Vite-проект со своим `package.json` и
`vite.config.js`, который через алиасы (`@core`, `@elements`, `@render`,
`@export`) подключает нужные ему пакеты.

## Как запустить инженерное приложение

Нужен Node.js (уже поставил) и один раз — установить зависимости.

Из VS Code: `` Ctrl+` `` откроет терминал внизу. Дальше:

```
cd apps/engineer
npm install
npm run dev
```

Вторая команда один раз скачает Vite и нужные библиотеки (`decimal.js`,
`clipper-lib`) — они не входят в этот архив, так как обычно не кладут
`node_modules` в поставку. После этого `npm run dev` откроет редактор в
браузере на `http://localhost:5173` (или похожем адресе — Vite покажет
ссылку в терминале) с автообновлением при сохранении файла.

Дальше можно оставлять `npm run dev` запущенным в фоне и просто
редактировать файлы — обновляться будет само.

## Что изменилось по сравнению со старой версией

- Все файлы `js/*.js` переведены на `import`/`export` вместо глобальных
  переменных и порядка `<script>`-тегов.
- `Decimal.js` и `ClipperLib` — теперь обычные npm-зависимости
  (`decimal.js`, `clipper-lib`), а не CDN-скрипты в `index.html`.
- Файл `js/elements/underframe.js` раньше сам лез в DOM (заполнял
  `<select>` с типами подстолья) — это вынесено в
  `apps/engineer/js/ui/underframe-options.js`, поскольку пакет с
  геометрией не должен трогать `document` напрямую (клиентское
  приложение в будущем не будет использовать `<select>` для этого вовсе).
- `js/ui/*.js` раньше писали/читали общий объект `UI = {...}`,
  собираемый порядком подключения скриптов. Теперь каждый файл явно
  экспортирует функцию-инициализатор (`initRender`, `initProjectIO`,
  `initHistory`, `initAutosave`, `buildElementManagers`), которые
  `apps/engineer/js/main.js` вызывает в правильном порядке, передавая
  зависимости явно — сам файл `main.js` документирует весь граф
  зависимостей, который раньше был неявным.
- Функционально ничего не изменилось: сохранение/загрузка проекта,
  история (localStorage), автосохранение и ссылка-шаринг
  (sessionStorage) работают как раньше — их чистку под офлайн-версию
  решили отложить на потом.
