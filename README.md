# DSK Editor — monorepo

## Структура

```
packages/            — общее, используется несколькими приложениями
  core/               — геометрия (geo.js), реестр слоёв (layers.js),
                        реестр элементов (elements.js), сборка чертежа (drawing.js)
  elements/           — каталог встраиваемых элементов (зарядки, розетки,
                        подстолье, кабель-каналы и т.д.)
  render/             — превью (SVG для экрана, размерные линии)
  export/             — DXF/SVG/PNG/G-code экспорт
  ui-preview/         — zoom.js (зум/пан превью), общий для engineer и geometry-editor
  shared-css/         — styles.css, общие визуальные токены для всех приложений

apps/                 — отдельные приложения поверх общего ядра
  engineer/           — сегодняшний редактор (полный функционал), Vite-проект
  geometry-editor/    — редактор геометрии отдельных элементов (для тонкой
                        правки координат/отверстий/скруглений в файлах
                        js/elements/*.js), Vite-проект
  client/             — ещё не создан (будущий шаг)

alias-loader.mjs       — резолвер алиасов (@core/@elements/...) для Node,
                          нужен только тестам (см. "Тесты" ниже)
```

Каждый пакет — обычные ES-модули (`import`/`export`), без сборки. Каждое
приложение в `apps/` — отдельный Vite-проект со своим `package.json` и
`vite.config.js`, который через алиасы (`@core`, `@elements`, `@render`,
`@export`, `@ui-preview`) подключает нужные ему пакеты.

## Как запустить

Нужен Node.js (уже поставил) и один раз — установить зависимости.

Из VS Code: `` Ctrl+` `` откроет терминал внизу. Дальше, для инженерного
редактора:

```
cd apps/engineer
npm install
npm run dev
```

Для редактора геометрии элементов — то же самое, но `cd apps/geometry-editor`.

Первая команда (`npm install`) один раз скачает Vite и нужные библиотеки
(`decimal.js`, для engineer ещё и `clipper-lib`) — они не входят в этот
архив, так как обычно не кладут `node_modules` в поставку. После этого
`npm run dev` откроет приложение в браузере (Vite покажет ссылку в
терминале, обычно `http://localhost:5173`) с автообновлением при
сохранении файла.

Дальше можно оставлять `npm run dev` запущенным в фоне и просто
редактировать файлы — обновляться будет само. Каждое приложение — свой
отдельный `npm run dev` (свой порт), можно держать оба открытыми.

## Тесты

У `geometry-editor` есть регрессионные тесты (перенесённые с реальным
`import`/`export` вместо старого `vm`-харнесса):

```
cd apps/geometry-editor
npm test
```

Тестам не нужен браузер — они гоняются в обычном Node, но исходники
пишут импорты вида `@core/geo.js`, которые сам Node не понимает без
подсказки (это чисто Vite-синтаксис). `alias-loader.mjs` в корне
монорепы — маленький резолвер под эти тесты, который учит Node тем же
алиасам, что уже знает Vite, так что сами исходники не нужно писать
по-разному для браузера и для тестов.

У `engineer` пока нет перенесённых тестов — это отдельный следующий шаг
(раньше там был тест на G-code экспорт, `gcode-smoke.test.js`, его ещё
нужно перевести на `import`).

## Что изменилось по сравнению со старой версией

- Все файлы `js/*.js` переведены на `import`/`export` вместо глобальных
  переменных и порядка `<script>`-тегов.
- `Decimal.js` и `ClipperLib` — теперь обычные npm-зависимости
  (`decimal.js`, `clipper-lib`), а не CDN-скрипты в `index.html`.
  CodeMirror (используется только в geometry-editor) остался CDN-скриптом
  — библиотека без активной npm-разработки под ES-модули, менять смысла
  не было.
- Файл `js/elements/underframe.js` раньше сам лез в DOM (заполнял
  `<select>` с типами подстолья) — это вынесено в
  `apps/engineer/js/ui/underframe-options.js`, поскольку пакет с
  геометрией не должен трогать `document` напрямую.
- `js/ui/*.js` (engineer) раньше писали/читали общий объект `UI = {...}`,
  собираемый порядком подключения скриптов. Теперь каждый файл явно
  экспортирует функцию-инициализатор (`initRender`, `initProjectIO`,
  `initHistory`, `initAutosave`, `buildElementManagers`), которые
  `apps/engineer/js/main.js` вызывает в правильном порядке, передавая
  зависимости явно.
- `js/zoom.js` раньше был скопирован вручную в `geometry-editor/js/` (с
  комментарием "если оригинал изменится — скопируй заново руками") —
  теперь это один файл, `packages/ui-preview/zoom.js`, на который
  ссылаются оба приложения.
- `styles.css` (общие токены) раньше подключался из `geometry-editor`
  по относительному пути наружу (`../css/styles.css`) — теперь это
  `packages/shared-css/styles.css`, чтобы не было связи между двумя
  приложениями напрямую через файловую структуру.
- **Обновление `geometry-editor` из твоей правки учтено**: новая модель
  `entries` вместо `groups` (текстовая панель теперь = буквально
  `parts:[...]` тело файла элемента, включая `...Holes.at(...)`), баг с
  нераспознаванием пар отверстий исправлен, `contour-list.js` и
  `ui-shim.js` убраны как мёртвый код. Все 4 теста (включая новый
  `holes-editing.test.js`) перенесены на реальные ES-импорты и проходят.
- Функционально в `engineer` ничего не изменилось: сохранение/загрузка
  проекта, история (localStorage), автосохранение и ссылка-шаринг
  (sessionStorage) работают как раньше — их чистку под офлайн-версию
  решили отложить на потом.

## Дальше

  (мастер настройки, каталог с картинками, калькулятор цены, заказ).
- Тесты `apps/engineer` (в т.ч. `gcode-smoke.test.js`) ещё не перенесены
  на реальные импорты.
- Сохранение в папку проектов через File System Access API для
  инженерного редактора — отдельный будущий шаг.
